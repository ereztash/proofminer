# ProofMiner — Commitment Gate DOD v1

Date: 2026-08-16
Authority: subordinate to `docs/TELOS_GOVERNANCE.md` v1.6.

This delta governs the first-session magic moment. It supersedes any lower-layer DOD item that optimizes the workspace, characterization depth or visual richness without improving commitment quality.

---

# A. Entry validity

A1. A real consequential professional transition is present.

A2. The user has at least one plausible action they are actually considering.

A3. Material resource exposure is represented when it matters: hours, money, deadline, attention or lock-in.

A4. The current plan is frozen before system challenge when a before/after comparison is needed.

**Fail:** recommendations appear before a valid baseline.

---

# B. Implied-bet reconstruction

B1. Every surfaced bet is traceable to a specific action / sequence / allocation.

B2. The UI says `your plan behaves as if...` or equivalent. It never silently attributes a conscious belief to the user.

B3. The user can correct, reject or refine the inferred bet with one low-friction action.

B4. When one action plausibly serves several mechanisms, ambiguity is retained rather than forced into one category.

B5. The system selects the highest-exposure unresolved bet rather than enumerating a taxonomy.

**Fail:** impressive assumption map with no decision consequence.

---

# C. Competing explanation gate

C1. A competing explanation is generated only when it could change a commitment outcome.

C2. The alternative must explain the same observed state through a meaningfully different mechanism.

C3. The system may state `we should rule this out`; it may not state the competitor is true without evidence.

C4. If no material competitor is justified, say so.

**Fail:** inventing alternatives to create drama or false balance.

---

# D. Evidence landscape

D1. Evidence is represented as relations to bets, not as an undifferentiated pile.

Allowed relations:

- `SUPPORTS`
- `CONTRADICTS`
- `NON_DISCRIMINATING`
- `MISSING`

D2. Evidence class remains visible where authority matters:

```text
F0 real behavior / outcome
F1 observed external evidence
F2 structural consequence
F3 hypothesis / scenario
F4 synthetic behavior
```

D3. User self-report cannot silently substitute for external buyer / market evidence.

D4. System-generated explanations cannot upgrade themselves into evidence.

D5. Research is requested only when the result can change `KEEP / CHANGE / TEST_FIRST`.

---

# E. Commitment outcome

The first-session reveal terminates in exactly one:

## KEEP

E1. The current plan survives the registered challenge.

E2. `KEEP` states what was tested and what remains uncertain.

E3. No surprise is manufactured to demonstrate value.

## CHANGE

E4. At least one real action, sequence, resource allocation, prerequisite or evidence acquisition changes.

E5. The before/after delta is visible.

## TEST_FIRST

E6. The unresolved claim is load-bearing.

E7. The protected commitment is materially larger / less reversible than the test.

E8. The test has at least two meaningful possible results with pre-registered consequences.

E9. Testing does not become default procrastination when cheap reversible action would teach faster.

**Fail:** `interesting insight`, `confidence score`, or `AI recommendation` presented as an outcome.

---

# F. Reversal and authorship

F1. Every load-bearing outcome states a reversal condition.

F2. The user can reject the system's interpretation without losing their baseline plan.

F3. Agreement with the system is not counted as authorship.

F4. The user can restate the commitment and why it is being kept / changed / tested in their own terms.

---

# G. Magic-moment observability

A first session is credited with a product-value moment only when at least one of the following is observed:

1. the user identifies a load-bearing bet they had not previously made explicit **and** it changes a commitment-relevant question;
2. the user changes action / order / allocation;
3. the user replaces a large commitment with a smaller discriminating test;
4. the prior plan survives a meaningful challenge and the user gains a concrete reversal condition they did not have before.

No credit for:

- surprise alone;
- praise;
- perceived intelligence;
- longer reflection;
- more objects in the workspace;
- user agreement with system language.

---

# H. Simplicity / substitute gate

H1. Compare against a strong simple advisor / LLM process.

H2. Commitment Gate must earn its extra structure through a unique decision-relevant distinction or lower total burden over the full decision.

H3. If a single strong prompt reliably produces the same commitment outcome and evidence discipline, collapse the product mechanism.

H4. If users mainly want execution service, do not reinterpret that as decision-support demand.

---

# I. Harm / failure gates

Hard fail if the mechanism:

- increases analysis paralysis without reducing a material commitment risk;
- repeatedly misinfers the plan's bet and requires extensive correction;
- treats strategic ambiguity as diagnostic certainty;
- systematically pushes users toward `TEST_FIRST`;
- makes reversible low-cost actions seem too dangerous to try;
- produces polished but non-discriminating research;
- causes system language to overwrite user reasoning;
- hides that an alternative is merely hypothetical.

```text

next_field_action

```

Primary questions:

- Did the Gate expose a unique load-bearing distinction?
- Did that distinction change a real commitment?
- Was the protected resource economically meaningful?
- Did later evidence support the value of the change / test?
- Did the mechanism reduce or increase indecision?
- Would the user pay before a comparable future commitment?
