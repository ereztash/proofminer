# Characterization FIELD Protocol — v1

Date: 2026-08-15

## Purpose

Test whether governed characterization meta-processes create **materially better professional-transition decisions** than a strong simple intake / advisory process.

The test is not whether self-application feels insightful.

The test is whether it changes a decision-relevant representation, research question, boundary, constraint, action ordering or allocation at justified cost.

---

# Primary hypothesis

> **When a professional has latent expertise relevant to their own transition, reconstructing that expertise from real cases, abstracting the operating model, self-applying it and challenging transferability will reveal decision-relevant structure that a strong generic intake misses.**

This is falsifiable.

---

# Participant fit

Prefer participants who:

- are in an active professional / market-position transition;
- have a real professional discipline / repeated practice they use to create value for others;
- face at least two plausible competing actions;
- control meaningful time / money / attention allocation;
- have at least one real prior professional case that can be reconstructed;
- have a live decision within the next 30–90 days.

Exclude or label cases where the user has no stable professional process to self-apply.

---

# Freeze before any intervention

Capture:

1. desired professional movement / O;
2. boundary / horizon;
3. current bottleneck representation;
4. planned actions and resource allocation;
5. why the participant expects those actions to work;
6. what would currently change their mind;
7. confidence / uncertainty in the plan.

Do not show the characterization hypothesis before the baseline is frozen.

---

# Arm S — strong simple process

A competent advisor performs a concise direct intake:

- target state;
- current state;
- audience / environment;
- constraints;
- alternatives;
- evidence already available;
- obvious dependencies;
- next material decision.

Then produces the strongest recommendation possible from that process.

Do not deliberately weaken this arm.

---

# Arm C — characterization-first process

Use only the smallest justified sequence.

## Step 1 — real-case extraction

Choose one actual professional case where the participant created value / made a meaningful judgment.

Elicit:

- situation;
- cue(s);
- what they checked;
- alternatives;
- dominant constraint;
- action / sequence;
- reversal condition;
- outcome.

## Step 2 — cross-case only if material

Ask for a second contrasting case only if one case is insufficient to decide whether a pattern is transferable.

## Step 3 — professional operating model

Summarize the smallest useful model and ask the user to correct it.

## Step 4 — self-application

Ask the participant to apply that model to their own business / transition as if it were a client / project / object of professional work.

## Step 5 — challenge

Explicitly test:

- boundary mismatch;
- transferability;
- competing lens;
- missing external evidence.

## Step 6 — research gap

Identify only the external unknowns that can still change the decision.

Then produce the recommendation / allocation.

---

# Primary comparison

Compare Arm C versus Arm S on **decision consequences**, not prose quality.

Record whether C uniquely changes:

- bottleneck representation;
- target / boundary;
- criterion;
- hidden constraint;
- dependency / sequence;
- alternative generated;
- information request;
- external research required;
- resource allocation;
- reversal condition.

For every claimed unique value ask:

> **Would the simple arm have reached this distinction with one additional direct question?**

If yes, the characterization layer may be unnecessary complexity.

---

# Efficiency evidence

Track:

- user minutes spent;
- number of questions;
- number of cases reconstructed;
- external research avoided / newly required;
- analysis time;
- whether the participant experienced repeated / unnecessary elicitation.

A better decision at 5× cost is not automatically a product win.

---

# Authorship check

After the recommendation, without displaying the model, ask:

- what did your own professional process reveal that you were not applying to yourself?
- what part of that transfer do you reject or qualify?
- which criterion is yours rather than the system's?
- what external evidence would make you abandon the self-applied conclusion?

The user must remain able to disagree with the extracted model.

---

# Outcome follow-up

At the next meaningful decision / outcome capture:

- what was executed;
- what happened;
- which characterization claim survived / failed;
- whether the professional operating model improved decision #2;
- whether the same lens became stale / misleading;
- whether an external lens was more useful than self-application.

---

# Falsification / kill conditions

The characterization-first hypothesis weakens materially if:

- strong simple intake reaches the same recommendation at materially lower cost;
- extracted professional models are too generic to discriminate actions;
- users already self-apply their professional process and no new distinction appears;
- self-application reinforces pre-existing bias more often than it exposes blind spots;
- external field evidence dominates the decision in most cases;
- the competing-lens challenge routinely invalidates the initial self-applied diagnosis;
- a single direct question recovers most of the value attributed to the meta-process;
- users enjoy the reflection but do not change research, decision or resource allocation.

---

# Strengthening evidence

The hypothesis strengthens when the characterization process repeatedly reveals a material distinction that:

1. was not present in the frozen baseline;
2. was not recovered by the strong simple process;
3. changes a real decision / research request / allocation;
4. remains intelligible and contestable to the participant;
5. survives or is usefully updated by later evidence.

---

# Stop rule

After each 3–5 suitable cases, rerun Telos Governance.

Do not continue collecting similar cases if the product decision is unchanged.

Possible outcomes:

- `CONTINUE` — another characterization family / case can change the decision;
- `COLLAPSE` — replace the meta-process with the simpler intake;
- `REPLAN` — characterization matters, but the current process is wrong;
- `FIELD-NEXT` — wait for execution / outcome / decision #2;
- `STOP-CELL` — further equivalent cases have low information value.
