# O recalled

Help a professional in a consequential transition improve how they understand the problem and allocate scarce resources toward a desired professional market / opportunity state, while preserving decision authorship and learning from real outcomes.

The system should exploit useful expertise already embedded in the user's professional practice, bring in external evidence where the user cannot know the outside world, and **stress-test the resulting strategy before consuming scarce real-world exposure**.

The purpose of pre-FIELD simulation is not to replace reality or maximize confidence. It is to increase `FIELD Yield`: remove internally discoverable failure modes, isolate `FIELD_DEBT`, and design the next real test so it can actually change a product / strategy decision.

---

# Primary transition

```text
A — rough professional destination
    + many plausible actions
    + limited resources
    + latent expertise / blind spots
    + uncertain outside world

        ↓

B — grounded, contestable transition representation
    + explicit boundary
    + useful endogenous expertise surfaced
    + external unknowns isolated
    + live decision framed
    + explicit strategy candidate
    + strategy stress-tested against plausible failure conditions
    + FIELD_DEBT isolated
    + resource allocation chosen
    + reversal evidence defined
    + next real-world test designed
```

The product does not pass B because an intake, research report, extracted methodology, map, simulation, recommendation or sophisticated framework exists.

# PHASE A — CHARACTERIZATION GATES

## A1 — No fixed-intake authority

A question exists because it can change a material representation, decision, boundary, research need or allocation — not because a schema contains the field.

## A2 — Baseline precedes intervention

Before advice preserve the user's stated target, bottleneck representation, planned actions, resource commitments, reasons and reversal conditions when material.

## A3 — Characterization process is selected, not assumed

The system can justify using or rejecting:

- direct clarification;
- critical-case reconstruction;
- cross-case abstraction;
- self-application / role reversal;
- resource / decision reconstruction;
- external mirror;
- competing-lens challenge;
- backward-from-O.

`SELF-APPLICATION` has no default authority.

## A4 — Real cases support material expertise claims

When the user's expertise is load-bearing, reconstruct actual professional episodes rather than relying only on abstract self-description.

## A5 — ProfessionalOperatingModel remains provisional and source-linked

Retain source cases, scope, uncertainties and transferability state.

## A6 — Cross-case abstraction is requisite, not ceremonial

Request an additional case only when one-case overgeneralization could change the decision.

## A7 — Self-application is bounded

The mapping states what corresponds, what does not, what is assumed and what decision implication follows.

## A8 — Professional-lens capture is challenged

Before self-application governs resources, test the material subset of boundary mismatch, transferability, competing lens, external evidence and authorship.

## A9 — Endogenous expertise is not external evidence

User expertise may identify what to inspect. It cannot substitute for buyer / market / competitor / channel facts when those are external.

## A10 — Characterization has a stop condition

At every extra question, case or lens ask:

> **What live representation or decision could this change?**

If none, stop.

# PHASE B — RESEARCH + DECISION GATES

## B1 — Decision-directed research

Every material research task has:

- `unknown`;
- `decision_affected` or `representation_affected`;
- evidence capable of changing the choice;
- source type;
- stop condition.

## B2 — Evidence boundaries remain explicit

```text
SOURCE → OBSERVATION → INFERENCE → TRANSFERABILITY → DECISION USE
```

Prevalence and chronology are not causal mechanism by default.

## B3 — Live decision precedes method selection

No MCDA / VOI / robust / optimization layer before the actual decision is explicit.

## B4 — Requisite reasoning

Use the least-complex sufficient process. Complexity must earn itself by changing a live decision or uncertainty.

## B5 — Constraints / dependencies outrank unnecessary scores

Hard feasibility and sequence are not hidden inside weights.

## B6 — Opportunity cost is explicit when material

The recommendation can state what is displaced / delayed / forgone.

## B7 — Information requests obey decision-value logic

If the answer cannot change a material decision, the request has no default claim to user effort.

## B8 — Deep uncertainty does not receive fake precision

Do not invent probabilities / scores to make a preferred framework usable.

## B9 — Staged decisions preserve options when useful

Represent action now, signposts, triggers and contingency path.

## B10 — Sensitivity controls analytical escalation

Stable recommendation under plausible variation → stop precision. Fragile recommendation → expose uncertainty and route to information / robustness / FIELD.

## B11 — Explicit strategy candidate exists before FIELD simulation

A material strategy must expose at least:

- O contribution;
- target actor / environment;
- mechanism hypothesis;
- prerequisites;
- resource commitment / opportunity cost;
- expected signal / horizon;
- reversibility / lock-in;
- load-bearing assumptions;
- stop / reversal conditions.

**Fail:** stress-testing an undefined theme such as `build authority` or `do more content`.

# PHASE C — STRATEGIC WIND TUNNEL GATES

## C1 — Wind Tunnel is used only when it can change strategy or FIELD design

Pre-FIELD stress testing is requisite, not a mandatory ritual.

**Fail:** running more scenarios / agents when no live decision or test can change.

## C2 — Field-likeness comes from evidence strength, not persona count

Use the evidence ladder:

```text
F0 — real field behavior / payment / action / outcome
F1 — current external observed evidence / real datasets
F2 — structural / logical consequence
F3 — plausible scenario assumption
F4 — synthetic stakeholder / LLM behavior
```

A lower class may not silently inherit the authority of a higher class.

## C3 — Structural kill tests precede synthetic simulation

Before role-playing buyers, attempt to detect:

- missing prerequisites;
- resource infeasibility;
- sequencing contradictions;
- boundary / transferability mismatch;
- circular evidence;
- metric gaming;
- non-discriminating tests;
- strategy requiring unowned authority / resources.

## C4 — Current external evidence is used before invented reactions

If F1 evidence can cheaply test a load-bearing factual assumption, acquire / use it before F4 simulation.

## C5 — Scenario analysis tests robustness, not prediction

Use only decision-relevant scenario families such as:

- resource shock;
- signal delay;
- competitor / substitute response;
- stakeholder veto;
- boundary shift;
- mechanism failure.

Every scenario states the assumption changed and what strategy decision could change.

## C6 — Synthetic stakeholders are hypothesis generators only

Synthetic buyers / competitors / gatekeepers may generate:

- objections;
- missing criteria;
- counter-moves;
- failure modes;
- interview hypotheses.

They may **not** validate:

- purchase intent;
- WTP;
- conversion;
- execution;
- retention;
- market response;
- prevalence.

Multiple synthetic agents agreeing does not upgrade evidence class.

## C7 — Assumption-flip / sensitivity boundary is explicit

For each load-bearing assumption, identify whether the strategy is:

- `ROBUST`;
- `CONDITIONAL`;
- `FRAGILE`;
- `BLOCKED`;
- `FIELD_ONLY`.

Do not collapse these to one confidence score by default.

## C8 — Pre-mortem must change something to survive

A failure story remains only when it changes:

- current action;
- signpost / monitoring;
- contingency;
- research;
- FIELD design.

Interesting failure narratives with no decision consequence are discarded.

## C9 — Strategy Delta is action-level

Wind Tunnel output must say what becomes:

`KEEP / ACCELERATE / REORDER / REDUCE / DELAY / STOP / REPLACE / ADD`.

Also record the evidence class that caused the change.

## C10 — FIELD_DEBT is mandatory before a FIELD outcome

Each load-bearing field-only item states:

- claim;
- why load-bearing;
- current strongest evidence;
- why simulation is insufficient;
- smallest real observation that can discriminate it;
- product / strategy decision changed by each result.

## C11 — FIELD Yield is explicit

Before consuming scarce participant / market exposure, ask:

- Does the test attack a load-bearing FIELD_DEBT item?
- Can the observation discriminate competing strategies / hypotheses?
- Are we testing something already knowable internally?
- Are unrelated uncertainties unnecessarily bundled?
- What decision changes for each possible result?

**Fail:** `talk to users` with no registered decision consequence.

## C12 — Wind Tunnel cannot certify FIELD truth

A simulation pass, scenario convergence or agent consensus cannot close a buyer / WTP / execution / outcome FIELD gate.

# PHASE D — REPRESENTATION / AUTHORSHIP / ALLOCATION GATES

## D1 — Representation change is inspectable

Show which bottleneck, mechanism, dependency, criterion or reversal condition changed.

## D2 — Agreement is not authorship

The user can explain, challenge, correct, change constraints and state reversal evidence in their own terms.

## D3 — Allocation states remain explicit

`KEEP / ACCELERATE / REORDER / REDUCE / DELAY / STOP / REPLACE / ADD`.

## D4 — Delta metrics have no routing authority

Representation / Allocation Delta are observational unless separately validated for a specific decision use.

## D5 — Boundary is inspectable

Domain, audience/environment, surface, horizon, exclusions and transfer limits are visible when material.

## D6 — One event may update multiple contexts

Record one event once and link all affected contexts.

## D7 — Learning may reverse prior advice

Professional-model, simulation and allocation conclusions must be reversible by real evidence.

# PHASE E — STRUCTURAL FALSIFICATION GATES

Before production automation, deterministic fixtures should reject at least:

1. advice before baseline;
2. self-application without a source operating model where one is claimed;
3. one-case rule promoted as broadly transferable without status;
4. professional rule crossing context without transferability judgment;
5. CharacterizationRun with no decision / representation purpose;
6. external research with no DecisionRelevantUnknown;
7. complex method escalation when simple dominance resolves the decision;
8. hard dependency hidden by score;
9. prohibited metric used in routing;
10. user agreement counted as authorship;
11. duplicated event identity across surfaces;
12. stale history reused without transferability check;
13. synthetic stakeholder output promoted to F0/F1 evidence;
14. FIELD outcome emitted with no FIELD_DEBT registry where material uncertainty exists;
15. proposed FIELD test unable to discriminate registered competing hypotheses;
16. extra Wind Tunnel pass with no strategy / test decision it can change.

These fixtures validate structural contracts, not strategic truth.

If Arm S repeatedly reaches the same material decision at lower cost, collapse characterization toward the simpler process.

### FIELD-only truths

Only real observation may materially update claims about:

- payment / refusal;
- actual user behavior;
- actual execution;
- buyer language prevalence;
- decision density;
- real market response;
- longitudinal compounding.
