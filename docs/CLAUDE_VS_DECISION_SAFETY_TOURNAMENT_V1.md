# ProofMiner — Claude Authority System vs Decision-Safety Capability

Date: 2026-08-16
Status: ADVERSARIAL PRODUCT TOURNAMENT

## Question

Two product theses now exist in the repository:

### A — Authority System (main / Claude)

A six-layer system that turns earned professional evidence into visible, measurable, compounding standing:

`PROOF → POSITION → ARTIFACT → RECEPTION → CONVERSION → RECOGNITION`

with a First Light reveal, one Next Move, evidence grounding, feedback loops, an Authority Index and a Visibility Gap.

### B — Decision-Safety Capability (agent/telos-governance-v3)

A delivery-form-neutral capability that reduces avoidable loss from consequential commitments under uncertainty:

`COMMITMENT → LOAD-BEARING BET → EVIDENCE / UNKNOWN → PASS | MODIFY | PROBE → OUTCOME`

with pre-influence capture, provenance, reversal conditions, strong-substitute kill tests and app non-entitlement.

The tournament does **not** ask which implementation is more complete.

It asks:

> Which thesis creates a recurring, high-value user need that is difficult to replace, produces real-world consequences, and remains epistemically defensible?

A third outcome is allowed: both theses die as products but survive as layers of a stronger product.

# Common judge

A thesis survives only to the degree it can satisfy the same gates.

| Gate | Question |
|---|---|
| J1 Pain proximity | Is the product solving the outcome the user actually wants, rather than an intermediate abstraction? |
| J2 First-session value | Can a new user experience material value before building a long history? |
| J3 Recurrence | Does the job naturally repeat often enough to create expectation and learning? |
| J4 Trigger clarity | Is there a recognizable moment when the capability should be used? |
| J5 Bounded context | Can useful support be produced without ingesting the user's entire digital life? |
| J6 World feedback | Does the world return a usable signal that can improve the next cycle? |
| J7 Compounding asset | Does repeated use create an asset a fresh generic chat cannot cheaply reconstruct? |
| J8 Substitute resistance | Does the thesis survive capable general AI + simple templates + adjacent software? |
| J9 Epistemic integrity | Does the product say only what its observables can justify? |
| J10 Support burden | Is the interaction cost lower than the value created? |
| J11 Action consequence | Does output change real action, allocation, sequence, evidence acquisition or external representation? |
| J12 Removal consequence | After demonstrated value, does absence cause compensatory behavior or observable loss? |

# A — Authority System attack

## What survives strongly

### A1 — Recurrence is real

The loop has natural repeated events: evidence capture, publishing / deployment, reception, conversion and recognition.

This is materially stronger than a product built around occasional broad professional-transition decisions.

### A2 — First Light is a credible activation hypothesis

"We found evidence in your own work that you were not treating as proof" can create value on the first session without requiring longitudinal data.

### A3 — The system reaches the world

Reception, replies, calls, proposals, deals, referrals and recognition are external signals. This gives the product a path from internal model to observable behavior.

### A4 — One Next Move is operational

The product can end in a concrete action rather than an analysis report.

### A5 — Engineering / integrity work is reusable

Keep the work on:

- deterministic extraction;
- Hebrew parity;
- safe import / XSS prevention;
- redacted secrets;
- demo quarantine;
- provenance;
- grounding limits stated honestly;
- confidence gating;
- source-linked feedback;
- test coverage.

These are implementation assets independent of the final product thesis.

## What fails / remains unearned

### A6 — "Authority" is probably an intermediate outcome

Independent professionals do not primarily want authority. They want opportunities, conversations, proposals, clients, income, choice and market mobility.

Job seekers want interviews and offers.

Authority may be a mechanism or latent state that helps produce those outcomes, but making it the telos risks optimizing an intermediate variable.

### A7 — The Authority Index is not entitled to cardinal interpretation

The code can be deterministic while the construct remains unvalidated.

A weighted composite of evidence, positioning, artifacts, reception, conversion and recognition is a model, not a directly observed quantity called "authority".

Deterministic arithmetic does not establish construct validity.

### A8 — The Visibility Gap overclaims even more

`gap = foundation - built` is mathematically defined inside the model, but the user-facing claim "your evidence supports 72; the world sees 19" implies two cardinal quantities with a common scale that have not been empirically established.

`built` is not literally "what the world sees". It is a constructed mixture of artifact, reception, conversion and recognition inputs.

**Kill as hero claim until validated.**

The internal distinction "strong evidence base / weak external activation" may survive without a fake-precise scalar.

### A9 — Strong substitutes attack the feature bundle

Current adjacent products already cover major pieces:

- LinkedIn creation, analytics, historical post analysis and reuse;
- AI-assisted personal-brand / influence creation;
- evidence-backed career portfolios;
- customer evidence libraries, ranking and proof recommendation.

Therefore ProofMiner cannot win merely by combining `evidence + content + analytics`.

### A10 — Manual measurement burden can kill the loop

If users must repeatedly type reception, conversion and recognition data, the loop may be theoretically closed and behaviorally abandoned.

The system must earn automation / low-friction capture or narrow itself to events users already have strong incentive to record.

### A11 — Two ICPs dilute the wedge

`job seeker` and `independent expert` share evidence primitives but do not share the same outcome function, trigger frequency, willingness to pay or conversion events.

**Kill the dual-ICP first wedge.**

# B — Decision-Safety attack

## What survives strongly

### B1 — Epistemic governance is materially stronger

Keep:

- user state != system inference != external evidence;
- pre-influence state;
- PASS / MODIFY / PROBE;
- reversal conditions;
- PROBE anti-paralysis rule;
- strong-substitute kill test;
- app non-entitlement;
- removal test;
- source-linked longitudinal claims.

These are strong governance properties for any decision-relevant product.

### B2 — It protects against the Authority System's largest risk

Decision-Safety gives the repository a mechanism for rejecting seductive but unsupported metrics, recommendations and product narratives.

## What fails / remains unearned

### B3 — The broad user need has weak pull

"Reduce avoidable loss from consequential professional commitments under uncertainty" is important but not usually a conscious recurring job users wake up wanting to perform.

The user has to notice a decision, classify it as consequential, and invoke a support capability.

### B4 — Broad professional transitions recur too slowly

Sparse, heterogeneous decisions weaken habit, learning, causal attribution and removal tests.

### B5 — Trigger detection is diffuse

A professional transition forms across messages, calls, drafts, outreach, content, meetings and private thought. There is no single clean commitment surface.

### B6 — General AI is a dangerous substitute

For many one-off decisions, a capable general AI + a short decision template can expose assumptions and alternatives at lower adoption cost.

### B7 — The product can become friction / hesitation

Even selective intervention risks destroying momentum. Without a narrow high-value trigger, Decision-Safety can become ceremony around action.

**Kill Decision-Safety as the standalone user-facing product thesis.**

Retain it as governance / an embedded capability.

# Verdict

## Neither A nor B survives as the product telos.

The tournament outcome is:

> **A supplies the stronger recurring user loop. B supplies the stronger epistemic and product governance. Neither should remain the user-facing category.**

The strongest synthesis is not `Authority + Decision Safety` as two modules.

It is a different hierarchy:

```text
USER OUTCOME
  ↓
PROOF → MARKET ACTION → OPPORTUNITY
  ↓
LONGITUDINAL EVIDENCE / RESPONSE MEMORY
  ↓
DECISION-SAFETY GOVERNOR
```

Working product thesis:

# Proof-to-Opportunity Layer

> **Help an independent expert turn evidence they have already earned into the next credible market action most likely to create a real opportunity — then learn from what actually happened.**

The user should not need to become a content creator or manage an "authority score".

# First wedge hypothesis

## Independent experts selling services

Do **not** start with the combined job-seeker + independent population.

Initial actor hypothesis:

- consultant / fractional / expert / specialist selling professional services;
- already has real work, outcomes, feedback, cases or professional traces;
- needs more or better commercial conversations;
- repeatedly sends DMs, follow-ups, proposals, case material, profile claims, talks or posts;
- does not want content production to become the job.

Why this actor first:

- market actions recur;
- commercial outcome is closer and more observable;
- proof can be matched to a buyer / objection / offer;
- willingness to pay can be tested against pipeline value;
- the same evidence can be reused across multiple external surfaces.

# The product loop that now has to earn existence

```text
1. MINE
   Recover earned evidence from real sources.

2. TARGET
   What buyer / opportunity / commercial action exists now?

3. SELECT
   Which evidence is most relevant and defensible for this context?

4. DEPLOY
   Use it in the smallest appropriate market action:
   outreach / follow-up / proposal / case / profile / post / talk.

5. TRACE
   Preserve what evidence, claim, audience and action were used.

6. OBSERVE
   Reply / conversation / proposal / deal / referral / rejection / no signal.

7. LEARN
   Update only what the observed data legitimately supports.

8. NEXT MOVE
   Recommend one next market action.
```

This is not a content loop. Publishing is one deployment surface among several.

# Decision-Safety's new role

Decision-Safety becomes the governor of the loop, not the product front door.

It asks only when material:

- Is this claim actually supported by the cited evidence?
- Is the system confusing inference with observation?
- Is the proposed move committing meaningful resource on a weak assumption?
- Is there a cheaper direct action or discriminating probe?
- What observation would reverse this recommendation?
- Is the current recommendation merely optimizing an internal score?

For cheap reversible market actions, the governor should prefer action over analysis.

# New indispensability DOD

The product is not indispensable because users like the dashboard or repeatedly check a score.

For one narrow market-action class, it must eventually satisfy all:

## P1 — Repeated real trigger
A market action recurs naturally: outreach, follow-up, proposal, pitch, case deployment or equivalent.

## P2 — Evidence selection changes
The system repeatedly surfaces or prioritizes evidence the user would not otherwise have used in the same way.

## P3 — Immediate action consequence
The evidence changes an external representation or action now.

## P4 — Groundedness
Every factual claim remains traceable to user-owned source material. No authority inflation.

## P5 — Outcome linkage
The system captures a real downstream signal without treating correlation as causation.

## P6 — Learning advantage
After repeated cycles, the accumulated proof-context-outcome history improves the next move beyond a fresh generic-AI conversation.

## P7 — Low burden
Capture and deployment are materially easier than maintaining a manual evidence spreadsheet + analytics workflow.

## P8 — Strong substitute test
Compare against:

- capable general AI;
- LinkedIn content / analytics tool;
- simple evidence vault / spreadsheet;
- manual advisor workflow.

ProofMiner must produce a material advantage in at least one of:

- evidence recovery;
- context-specific proof selection;
- provenance / integrity;
- cross-surface deployment;
- outcome-linked learning;
- reduced workflow burden.

## P9 — Removal test
After demonstrated value, remove the capability for one repeated market action.

Strong evidence:

- user manually searches for prior proof;
- user recreates the proof-selection step;
- user delays / changes the action because the capability is missing;
- user explicitly accepts a known loss and proceeds.

Fail:

- user sends / publishes / proposes exactly as before and does not notice a material loss.

## P10 — Commercial test
A suitable independent expert is willing to pay to preserve the capability because its expected value is tied to opportunities / pipeline, not to engagement vanity metrics.
