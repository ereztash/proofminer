# FIELD Protocol v5.0

Date: 2026-08-16

## Purpose

Test the live product mechanism in the order reality can falsify it **while maximizing the information value of each scarce real-world exposure**.

Current product claim:

> A professional-transition decision system can create additional value by selecting only the characterization needed, extracting useful latent expertise from real professional cases when relevant, challenging transferability, researching only decision-relevant external unknowns, constructing an explicit strategy / allocation candidate, stress-testing that candidate before exposure, and then using real behavior / payment / outcomes to resolve the remaining FIELD_DEBT.

This protocol coordinates:

- `CHARACTERIZATION_FIELD_PROTOCOL_V1.md`;
- `STRATEGIC_WIND_TUNNEL_GOVERNANCE_V1.md`;
- `skills/strategy-wind-tunnel/SKILL.md`;
- `COMMERCIAL_FIELD_PROTOCOL_V1.md`;
- `PAID_FIELD_OFFER_V1.md`.

Do not confuse mechanism validation, simulated robustness, strategic correctness, willingness to pay and retention.

---

# Governing rules

- Freeze the user's baseline before exposing the mechanism.
- Do not explain what the user was supposed to experience.
- Do not reward novelty / insight language unless it changes a material decision.
- Do not infer authorship from agreement.
- Do not infer strategic truth from model / reviewer / synthetic-agent agreement.
- Do not optimize for larger Representation or Allocation Delta.
- Do not run self-application when it has no decision-relevant purpose.
- Do not research externally before identifying the unknown that research is meant to resolve.
- Do not run more Wind Tunnel scenarios when they cannot change strategy or FIELD design.
- Synthetic stakeholders are `F4` hypothesis generators only; they cannot close payment / behavior / outcome gates.
- Before using a suitable participant, register the material `FIELD_DEBT` that the participant can help resolve.

---

# Evidence classes

Preserve:

```text
F0 — real field observation / payment / action / outcome
F1 — current external observation / real dataset / credible public market evidence
F2 — structural / logical consequence
F3 — plausible scenario assumption
F4 — synthetic stakeholder / LLM-generated behavior
```

A believable F4 output remains F4.

---

# Wave 0 — Trigger / fit

Before intervention capture in the user's language:

- what professional change is happening now;
- why it matters now;
- what decision / resource tension exists;
- what they currently expect to do;
- what would make the process valuable;
- whether they primarily want a better decision or execution done for them.

Do not introduce `Decision Intelligence`, `authority`, `market position`, `characterization`, or internal category vocabulary before capturing the struggling-moment language.

If the participant mainly wants execution, preserve that as product-category evidence rather than coaching them into decision support.

---

# Wave 1 — Freeze baseline

Before any advice or characterization capture:

1. target state / O;
2. project / decision boundary;
3. current bottleneck / mechanism representation;
4. planned actions;
5. intended ordering;
6. material resource allocation;
7. why those actions should work;
8. current constraints;
9. current change / reversal conditions;
10. confidence / uncertainty.

This is a stated counterfactual, not causal truth.

---

# Wave 2 — Strong-Simple shadow analysis

Before running the richer mechanism, create and freeze a competent simple advisory result using only the information a strong advisor could reasonably obtain without the characterization architecture.

```text
O / boundary
→ state
→ constraints
→ alternatives
→ obvious external evidence when required
→ recommendation
```

Record:

- representation;
- information requests;
- recommendation;
- allocation;
- uncertainty;
- analyst effort.

Do not deliberately weaken this arm.

When contamination would be severe, keep this as an internal shadow rather than showing it to the participant first.

---

# Wave 3 — Characterization discrimination

Use `CHARACTERIZATION_FIELD_PROTOCOL_V1.md`.

Select the **smallest justified** process.

When expertise is genuinely material:

```text
real case(s)
→ Professional Operating Model
→ self-application if useful
→ transferability / competing-lens challenge
→ DecisionRelevantUnknowns
→ targeted external research
```

Primary question:

> **Did characterization reveal a material distinction that Strong Simple did not recover at lower cost?**

Record unique contribution by type:

- representation;
- boundary;
- criterion;
- hidden constraint;
- dependency;
- new alternative;
- information request;
- research avoided / newly required;
- allocation;
- reversal condition.

If no unique material distinction appears, do not protect characterization because it felt insightful.

---

# Wave 4 — Build explicit strategy candidate

Before the Wind Tunnel, represent the resulting recommendation as an actual strategy candidate:

- intended contribution to O;
- target actor / environment;
- mechanism hypothesis;
- prerequisites;
- action sequence;
- resource commitment / opportunity cost;
- expected signal / horizon;
- reversibility / lock-in;
- load-bearing assumptions;
- stop / reversal conditions.

Do not stress-test a vague theme.

---

# Wave 5 — Internal Strategic Wind Tunnel

Run `skills/strategy-wind-tunnel/SKILL.md` internally before the participant sees the final recommendation when the Wind Tunnel can materially change the strategy or FIELD test.

Use the smallest useful subset of:

- structural kill tests;
- current external evidence contradiction;
- resource shock;
- signal delay;
- competitor / substitute response;
- stakeholder veto;
- boundary shift;
- mechanism failure;
- assumption-flip / sensitivity;
- pre-mortem.

Synthetic stakeholders may be used only after evidence grounding and only to generate hypotheses / objections.

Required internal output:

- `STRATEGY_DELTA`;
- `ROBUST_CORE`;
- `CONDITIONAL_MOVES`;
- evidence classes used;
- `FIELD_DEBT`;
- next discriminating real-world observations.

### Wind Tunnel collapse rule

Skip or stop the Wind Tunnel if it cannot change:

- recommendation;
- resource allocation;
- uncertainty boundary;
- signpost / reversal condition;
- FIELD test design.

The participant is not paying to watch an internal simulation exercise.

---

# Wave 6 — FIELD_DEBT registration

Before exposing the final recommendation / commercial offer, register the load-bearing uncertainties that reality still owns.

For each item:

```text
claim
why_load_bearing
strongest_current_evidence
why_internal_simulation_is_insufficient
smallest_real_observation
possible_outcomes
product_or_strategy_decision_changed
```

Current expected classes include, when material:

- Characterization unique contribution;
- buyer problem language;
- decision support vs execution substitute;
- willingness to pay;
- actual execution;
- market response;
- natural decision density;
- longitudinal history materiality.

Do not invent a field test for an uncertainty that no longer changes a decision.

---

# Wave 7 — Recommendation / authorship value

Now expose the grounded, stress-tested recommendation — not the internal simulation trace unless explanation requires it.

Capture:

- revised representation;
- revised allocation;
- what uniquely changed it;
- which endogenous / external evidence mattered;
- what part of the Professional Operating Model the user endorses;
- what part they reject / bound;
- what they will actually do;
- what they will not do yet;
- what evidence would reverse the decision.

Authorship prompts:

> What criterion are you now using in your own words?

> What would you challenge in the system's model?

> If one important constraint changed, what should happen to the recommendation?

A participant who can repeat the recommendation but cannot contest it fails authorship.

---

# Wave 8 — Commercial evidence

Only after one real decision intervention has produced an observable consequence for the participant's plan, use `PAID_FIELD_OFFER_V1.md`.

Current frozen first price cell:

> **90-Day Professional Market Position Decision Intelligence Pilot — $1,500 total.**

Record actual:

- paid;
- deposit / committed payment date;
- refusal at price;
- not offered with reason.

Do not replace refusal with stated interest.

Commercial attribution question:

> **Was the value in characterization, external research, the allocation decision, the Wind Tunnel / risk reduction, human judgment, execution support, or the combination?**

Do not infer the answer from what the participant compliments. Prefer the reason attached to a real purchase / refusal / continuation behavior.

---

# Wave 9 — Execution / outcome

At follow-up capture:

- actual action;
- actual resource use where feasible;
- outcome / market signal;
- affected contexts / surfaces;
- which characterization hypothesis survived;
- which transfer assumption failed;
- which Wind Tunnel scenario / signpost became relevant;
- which recommendation changed;
- regret / reversal.

Do not certify a poor process because the outcome was lucky.

Do not punish a sound decision solely because one uncertain outcome was weak.

---

# Wave 10 — Decision #2 / compounding value

At the next natural consequential decision ask:

1. what prior Professional Operating Model / decision history is actually relevant?
2. what must be ignored because the context changed?
3. does prior history materially change representation, research, Wind Tunnel stress tests or allocation versus a fresh intake?
4. does characterization need to run again, partially, or not at all?
5. did prior FIELD evidence remove uncertainty that would otherwise have to be re-researched?

Run a fresh-shadow comparison where feasible.

Longitudinal value passes only when prior evidence changes a material decision element **after transferability review**.

---

# Wave 11 — Meta-decision router, only if still material

Do not test adaptive decision-method selection merely because it exists in the architecture.

Test it only when two otherwise-comparable cases have materially different decision structures and method selection could change the recommendation / information request.

If a strong fixed process repeatedly matches it at lower cost, collapse the router.

---

# FIELD Yield test

After each suitable participant ask:

- Which registered FIELD_DEBT item did this exposure actually update?
- Did the observation discriminate competing strategies / hypotheses?
- Did we spend user / market exposure on something we could have resolved internally?
- What product decision changed?
- What new FIELD_DEBT, if any, was created?

A session that generates interesting feedback but does not update a load-bearing decision is low-yield evidence.

Do not compensate by simply adding more participants of the same kind.

---

# 95% structural assurance layer

Appropriate deterministic targets include:

- advice before baseline;
- CharacterizationRun without decision / representation purpose;
- self-application without source Professional Operating Model when required;
- one-case rule promoted without transferability state;
- external research without DecisionRelevantUnknown;
- hard constraint ignored;
- prohibited metric used for routing;
- user agreement counted as authorship;
- stale history reused without transferability check;
- synthetic stakeholder output promoted to F0/F1;
- FIELD outcome with no FIELD_DEBT while load-bearing uncertainty remains;
- FIELD test whose outcomes cannot change any registered product / strategy decision;
- refuted assumption remains active.

These tests can strongly assure structural compliance in a defined scope. They do not prove strategic correctness.

---

# Stop / replan rules

After each 3–5 suitable cases — or earlier if accumulated evidence already changes the product decision — rerun Telos Governance.

## Collapse characterization if

- Strong Simple reaches the same material decision at lower user/system cost;
- self-application mostly reproduces existing beliefs;
- extracted Professional Operating Models are generic / non-discriminating;
- boundary challenges invalidate most transferred expertise;
- external evidence dominates nearly all cases.

## Collapse / shrink Wind Tunnel if

- it repeatedly produces no strategy / FIELD-design delta;
- synthetic hypotheses dominate the output despite weak grounding;
- real users repeatedly surprise the same supposedly robust simulation patterns;
- pre-FIELD time / complexity exceeds the field-exposure saved;
- a much smaller structural + evidence checklist yields the same FIELD_DEBT.

## Strengthen characterization / Wind Tunnel if

- they repeatedly expose material constraints / dependencies / assumptions missed by the simpler process;
- they materially improve FIELD-test discrimination;
- they reduce wasted participant exposure;
- later F0 evidence validates useful signposts or correctly triggers replanning.

## FIELD-NEXT

Wait for real execution / payment / outcome / next decision when internal analysis cannot resolve the registered FIELD_DEBT.

Do not create another UI prototype or more synthetic personas merely to stay busy.
